# 浏览器操控

## 首选工具
- **browser_navigate**：导航到指定 URL，返回页面标题、文字内容和可交互元素列表。任何网页操作的第一步。
- **browser_get_content**：获取当前页面的标题、URL、文字内容和可交互元素（链接、按钮、输入框等）。当需要了解当前页面状态或查找可操作元素时使用。
- **browser_click**：点击页面上的元素（通过 CSS 选择器或可见文字定位）。点击后自动返回更新后的页面状态。
- **browser_type**：在输入框中输入文字。用于填写搜索框、表单等。
- **browser_scroll**：上下滚动页面（每次 500px）。当需要的内容不在首屏时使用。
- **browser_go_back**：返回上一页。
- **browser_screenshot**：对当前页面截图，返回 base64 编码的图片。用于需要视觉查看的场景（图表、验证码、布局确认等）。
- **browser_execute_js**：在页面中执行 JavaScript 代码并返回结果。用于高级数据提取或复杂交互。
- **browser_get_qrcode**：从当前页面提取二维码图片（base64），用于扫码登录。自动搜索页面中 QR 相关的 img/canvas 元素并裁剪截图。
- **browser_wait_for_login**：等待扫码或验证码提交后页面跳转（最长 120 秒）。轮询检测 URL 变化或登录成功标识。

## 工具使用策略

### 🚨 最高优先级规则：用户说已登录就绝对不要登录

**当用户说「已经登录过了」「不需要登录」「不用再登录」「我登录了」或任何表达"已登录"的话时：**

1. **立即停止**所有登录相关操作（不要再点「登录」按钮、不要再调 get_qrcode、不要再填手机号）
2. 如果当前页面显示的是登录页（而非已登录状态），向用户说明：「当前页面显示的是登录页，浏览器可能没有您之前的登录记录。如果您需要我帮您操作，需要在这个浏览器里重新登录一次。要继续吗？」
3. 如果用户确认要登录，再走场景七/八的流程
4. **绝对禁止**在用户说已登录后，还在同一个 tool call 序列里继续点「登录」按钮或填手机号

> 为什么有这个规则？浏览器每次重启都是全新环境，没有 cookie。用户在其他地方（手机、自己电脑）的登录不会同步到这里。所以当你看到登录页时，先解释原因，等用户决定，不要自作主张。

### 其他工具策略

1. **优先调用浏览器系列工具**：直接操控真实浏览器，能处理动态渲染页面、JS 生成内容、需要登录的页面等。
2. **失败降级**：如果浏览器工具调用失败（如 Chromium 未安装、页面加载超时），改用 web_search / brave_web_search 搜索相关信息，并告知用户浏览器不可用。
3. **不要跳过 get_content**：在不确定页面状态时，先用 browser_get_content 了解当前页面有哪些可交互元素，再决定下一步操作。
4. ⚠️ **登录优先扫码**：需要登录时，必须先调用 browser_get_qrcode 尝试获取二维码。只有确认没有二维码选项，才降级到短信验证码登录。
5. ⚠️ **自动操作**：填手机号、填验证码、点击按钮全部由 browser_type 和 browser_click 自动完成。唯一需要用户参与的：提供手机号、提供验证码、扫描二维码。

## 场景一：在搜索引擎上搜索信息

### 执行流程
1. **构造搜索 URL**：将用户搜索关键词拼接到搜索引擎 URL 中。
   - 百度：`https://www.baidu.com/s?wd=关键词`
   - 必应：`https://www.bing.com/search?q=关键词`
2. **导航到搜索结果页**：调用 `browser_navigate`，传入构造好的 URL。
3. **查看搜索结果**：navigate 返回的内容已包含搜索结果摘要，直接提取关键信息答复用户。
4. **如需深入查看**：调用 `browser_click` 点击某条结果的链接，进入详情页查看。

### 示例
用户说"帮我在百度搜一下杭州天气"：
1. `browser_navigate("https://www.baidu.com/s?wd=杭州天气")`
2. 从返回的页面内容中提取天气信息
3. 整理后回复用户

## 场景二：访问指定网站提取信息

### 执行流程
1. **确认 URL**：明确用户要访问的网址。如果用户只说了网站名（如"淘宝"），补全为 `https://www.taobao.com`。
2. **导航**：调用 `browser_navigate`，传入完整 URL。
3. **查看页面内容**：navigate 返回的结果已包含页面文字和可交互元素列表。
4. **如果需要更多内容**：调用 `browser_scroll` 向下滚动，再用 `browser_get_content` 获取新内容。
5. **提取信息**：从页面内容中提取用户关心的信息，整理回复。

### 注意事项
- 部分网站可能反爬或需要登录，此时告知用户页面需要登录，并建议用户在真实浏览器中操作。
- 动态加载的页面（如社交媒体时间线）需要配合 scroll 多次滚动加载。

## 场景三：表单填写与交互

### 执行流程
1. **导航到目标页面**：`browser_navigate` 访问含表单的页面。
2. **查看表单元素**：从 navigate 返回的「Interactive elements」中确认输入框和按钮的 CSS 选择器。
3. **填写输入框**：调用 `browser_type`，传入选择器和要输入的文本。多个字段逐个填写。
4. **点击提交**：调用 `browser_click` 点击提交/搜索按钮。
5. **查看结果**：click 返回的页面状态即为提交后的结果页面。

### 示例
用户说"帮我在百度搜索框输入'Java 21 新特性'然后搜索"：
1. `browser_navigate("https://www.baidu.com")`
2. 从返回的交互元素中找到搜索框的选择器（通常是 `#kw`）
3. `browser_type("#kw", "Java 21 新特性")`
4. 从交互元素中找到搜索按钮（通常是 `#su`）
5. `browser_click("#su")`
6. 从返回的搜索结果页面中提取信息回复用户

### 注意事项
- ⚠️ 不要在同一个 tool call 中连续填表后直接提交敏感操作（如支付、删除、下单）。涉及资金、账号的操作必须先展示确认页面给用户，等用户明确确认后再执行。
- 填写表单前先用 get_content 确认当前页面的表单字段，选择器可能因页面版本不同而变化。

## 场景四：截图查看

### 适用情况
- 页面内容无法通过文字提取（图表、图片、地图等）
- 需要查看页面的视觉布局
- 用户明确要求"截图给我看"

### 执行流程
1. 先完成需要的页面操作（导航、点击、滚动等）
2. 调用 `browser_screenshot` 截取当前视口
3. 截图结果中包含 base64 编码的图片数据，可以直接展示给用户

---

## 场景五：动态内容加载（无限滚动 / 加载更多）

### 执行流程
1. **导航到页面**：`browser_navigate` 访问目标页面。
2. **判断是否需要滚动**：如果用户需要的内容在首屏之后，或页面是动态加载的（如新闻列表、社交媒体）。
3. **滚动加载**：多次调用 `browser_scroll("down")`，每次滚动后页面会自动加载新内容。
4. **提取内容**：调用 `browser_get_content` 获取累计加载的内容。
5. **重复直到获取足够内容**：通常滚动 2-5 次即可覆盖大部分需求。

## 场景六：JavaScript 高级数据提取

### 适用情况
- 页面内容无法通过文字提取获取（数据在 JS 变量中）
- 需要批量提取特定元素属性
- 需要触发自定义事件

### 执行流程
1. 先通过 navigate/get_content 了解页面结构
2. 编写合适的 JS 脚本提取数据
3. 调用 `browser_execute_js` 执行

### 示例脚本
```
// 提取所有文章标题
Array.from(document.querySelectorAll('h2.title')).map(el => el.textContent).join('\n')

// 提取所有图片 URL
Array.from(document.querySelectorAll('img')).map(el => el.src).filter(Boolean).join('\n')
```

## 场景七：扫码登录（二维码登录）

### 适用情况
- 网站要求微信/支付宝/App 扫码登录
- 页面显示二维码后等待用户手机扫码确认
- 适用于小红书、B站、知乎、微博等大多数国内网站的登录

### 执行流程
1. **导航到登录页**：`browser_navigate` 访问目标网站的登录页。
2. **查看页面**：`browser_get_content` 了解登录页的布局，确认有二维码登录选项。
3. **切换到二维码登录**（如需要）：如果默认是密码/短信登录，调用 `browser_click` 点击「扫码登录」「二维码登录」等 tab。
4. **提取二维码**：调用 `browser_get_qrcode` 获取二维码的 base64 图片。
5. **展示给用户**：将二维码图片展示给用户，告知用户用对应 App 扫码。
6. **等待扫码**：调用 `browser_wait_for_login`（建议 60 秒超时），轮询等待页面跳转。
7. **确认登录成功**：wait_for_login 返回后，页面应该已跳转到登录后的首页。调用 `browser_get_content` 确认登录状态。

### 示例
用户说"帮我登录小红书"：
1. `browser_navigate("https://www.xiaohongshu.com")`
2. 检测到需要登录 → 查找登录入口 → `browser_click` 点击「登录」
3. 确认是二维码登录页 → `browser_get_qrcode`
4. 将二维码发给用户：「请用小红书 App 扫描此二维码完成登录」
5. `browser_wait_for_login(60)` 等待用户扫码
6. 登录成功后告知用户

### 注意事项
- ⚠️ 二维码可能有有效期（通常 2-5 分钟），如果 `wait_for_login` 超时，调用 `browser_get_qrcode` 重新获取新二维码
- 有些网站扫码后需要用户在手机上点「确认登录」，需要在提示中告知用户

## 场景八：手机验证码登录（仅当二维码不可用时的降级方案）

### ⚠️ 前提：必须先尝试场景七（扫码登录），确认页面没有二维码选项后才能走短信登录。

### 执行流程
1. **切换到短信登录**（如需要）：`browser_click` 点击「手机验证码登录」「短信登录」等 tab。
2. **询问手机号**：告知用户该网站需要手机验证码登录，询问是否愿意提供手机号。
3. **填入手机号**：用户提供手机号后，**立即自动**调用 `browser_type` 填入手机号输入框。
4. **点击获取验证码**：**立即自动**调用 `browser_click` 点击「获取验证码」「发送验证码」按钮。不要叫用户自己去点！
5. **等待用户提供验证码**：告知用户验证码已发送，请用户回复验证码。
6. **填入验证码并登录**：用户回复验证码后，**立即自动** `browser_type` 填入验证码输入框，然后**立即自动** `browser_click` 点击「登录」「确认」按钮。
7. **确认结果**：`browser_get_content` 或 `browser_wait_for_login` 查看登录后的页面状态。

### ⚠️ 关键规则
- **所有点击操作由你自动完成**（browser_click），不要叫用户去点按钮
- 填手机号 → 你来做（browser_type）
- 点发送验证码 → 你来做（browser_click）
- 填验证码 → 你来做（browser_type）
- 点登录 → 你来做（browser_click）
- 用户只需要提供：手机号、收到的验证码

## 严格禁止的行为

1. ❌ **禁止在未经用户确认的情况下执行支付、下单、删除等不可逆操作**：浏览器工具可以操控任何网页，但涉及资金、账号安全的操作必须先告知用户并等待确认。
2. ❌ **禁止未经用户明确同意就输入手机号**：在场景八（验证码登录）中，必须先询问用户是否愿意提供手机号，用户明确回复手机号后才能填入。绝不允许从任何存储中读取用户手机号自动填入。
3. ❌ **禁止输入或提交用户密码、身份证等不可逆敏感信息**：密码、身份证号等绝对不能代填。验证码属于临时凭证，在用户主动提供后可以代填。
3. ❌ **禁止访问违法违规网站**：包括但不限于赌博、色情、诈骗、侵权网站。
4. ❌ **禁止在同一个 navigate 调用中访问未知/不可信的短链接**：先告知用户目标 URL，等用户确认。
5. ❌ **禁止无限循环点击/滚动**：如果连续 3 次操作后仍找不到目标内容，停止操作并告知用户，改用 web_search 作为替代方案。
6. ❌ **禁止用 CSS 选择器盲目猜测**：不确定选择器时，先用 browser_get_content 查看页面上的可交互元素列表，从中找到准确的选择器。
7. ❌ **禁止跳过 navigate 直接 click/type**：必须先导航到目标页面，再进行交互操作。
